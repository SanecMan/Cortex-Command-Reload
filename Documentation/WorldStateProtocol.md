# World-state protocol foundation

The new protocol starts with explicit little-endian serialization rather than sending C++ structs or framebuffer pixels. Version 1 defines a full `WorldSnapshot` packet with a server tick, scene revision, UTF-8 activity and scene preset names, and a list of objects. Each object record carries a stable server-assigned network ID, class/module/preset names, transform and velocity, health, team, and flags.

The 16-byte packet header contains the `CCR1` magic, protocol version, message type, reserved byte, sequence number, and payload length. The decoder rejects unknown versions and message types, truncated or oversized packets, invalid UTF-8, non-finite numeric values, duplicate/zero object IDs, and object/string counts beyond fixed bounds. It does not rely on compiler struct packing or endianness.

`-debug-run` performs an in-process round-trip check with a Cyrillic preset name and verifies that truncated packets, unsupported versions, and duplicate network IDs are rejected. The codec is transport-independent so it can be carried over the repository's RakNet dependency.

`WorldStateSnapshotBuilder` captures top-level actors, items, and particles from `MovableMan`. It uses the host process's monotonic `MovableObject` runtime UIDs as network IDs, increments the scene revision when the Activity or Scene instance/preset changes, and marks actor/item/particle categories in object flags. At the end of its automated gameplay smoke run, debug mode broadcasts this snapshot through a local RakNet server to four clients. Each client decodes it and checks the tick, scene, object count, and first preset name; the run also repeats capture to verify IDs and scene revision remain stable. Packet size and pass/fail go to `ScreenShots/DebugRuns/DebugRun.log`. Attached equipment and actor inventories, terrain state/deltas, and object creation/deletion history are not captured by this diagnostic snapshot. Runtime UIDs are only unique within the host process and still need session/lifecycle policy for reconnects and server restarts.

`WorldStateTransport` is the RakNet adapter for connected peers. In addition to raw versioned packets, its typed `SendSnapshot` and `BroadcastSnapshot` methods encode a `WorldStateProtocol::Snapshot` with the caller's tick/sequence before reliable ordered delivery. The automated debug run first checks a representative packet before loading content, then broadcasts the live actor/item/particle stress scene to four clients and verifies their decoded sequence. Debug runs skip audio initialization to avoid a native FMOD worker-thread shutdown crash reproduced on Linux; Windows and Ubuntu 24.04 offscreen runs pass after this change. Normal game launches keep their existing audio behavior. This validates local snapshot transport only; gameplay joining, authoritative input handling, snapshot reconciliation, and headless server startup remain required before this can be used as multiplayer.

The legacy framebuffer `NetworkServer` and `NetworkClient` sources remain excluded from both build systems and implement a different remote-frame protocol. The new RakNet transport can exchange snapshots, but there is not yet an in-game client receiver or authority loop. Object lifecycle reconciliation, client input authority, terrain delta replication, and headless simulation still need integration before this protocol is exposed to players.
