# World-state protocol foundation

The new protocol starts with explicit little-endian serialization rather than sending C++ structs or framebuffer pixels. Version 1 defines a full `WorldSnapshot` packet with a server tick, scene revision, UTF-8 activity and scene preset names, and a list of objects. Each object record carries a stable server-assigned network ID, class/module/preset names, transform and velocity, health, team, and flags.

The 16-byte packet header contains the `CCR1` magic, protocol version, message type, reserved byte, sequence number, and payload length. The decoder rejects unknown versions and message types, truncated or oversized packets, invalid UTF-8, non-finite numeric values, duplicate/zero object IDs, and object/string counts beyond fixed bounds. It does not rely on compiler struct packing or endianness.

`-debug-run` performs an in-process round-trip check with a Cyrillic preset name and verifies that truncated packets, unsupported versions, and duplicate network IDs are rejected. The codec is transport-independent so it can be carried over the repository's RakNet dependency.

`WorldStateSnapshotBuilder` captures top-level actors, items, and particles from `MovableMan`. It assigns monotonically increasing server network IDs and tracks them against host-local runtime UIDs for each live object's lifetime; stale mappings are removed after the object disappears. It increments the scene revision when the Activity or Scene instance/preset changes and marks actor/item/particle categories in object flags. At the end of its automated gameplay smoke run, debug mode broadcasts this snapshot through a local RakNet server to four clients. Each client decodes it and checks the tick, scene, object count, and first preset name; the run also repeats capture to verify IDs and scene revision remain stable. Packet size and pass/fail go to `ScreenShots/DebugRuns/DebugRun.log`. Attached equipment and actor inventories, terrain state/deltas, and object creation/deletion history are not captured by this diagnostic snapshot. Network IDs are local to a host session and restart when that session is recreated.

`WorldStateTransport` is the RakNet adapter for connected peers. Its typed `SendSnapshot` and `BroadcastSnapshot` methods encode snapshots before reliable ordered delivery. `WorldStateClientSession` handles connection events, validates snapshots, rejects stale sequences, and retains the latest decoded state; it does not yet reconcile state into `MovableMan`. With `-world-state-server`, an in-process host session polls joins/leaves and broadcasts current snapshots at 20 Hz from the simulation loop. The debug run connects four client sessions to this actual host, confirms all receive a snapshot, disconnects them, and verifies the host stays alive. It separately exercises raw transport and malformed protocol packets. Windows and Ubuntu 24.04 offscreen debug runs pass. Debug runs skip audio initialization to avoid a native FMOD worker-thread shutdown crash reproduced on Linux; normal game launches keep their existing audio behavior. These checks verify local session wiring, not remote gameplay synchronization.

The legacy framebuffer `NetworkServer` and `NetworkClient` sources remain excluded from both build systems and implement a different remote-frame protocol. An experimental host can be started with `Cortex Command.debug.minimal.exe -world-state-server 8000 -world-state-bind 0.0.0.0 -world-state-players 8`. It starts the built-in Tutorial Activity, listens on the chosen IPv4 address/port, accepts up to 64 RakNet peers, broadcasts snapshots at 20 Hz while simulation updates, and writes connection/status messages to `WorldStateServer.log`. The port is optional (default `8000`); bind address and player limit default to `0.0.0.0` and `8`. Closing the game stops the session. This host is still the ordinary graphical client process: it initializes SDL and rendering, and it does not yet support configurable Activity/Scene, a gameplay client receiver/reconciliation path, authoritative input, terrain replication, or a standalone headless executable. Non-snapshot client packets are currently rejected. This is a server-session foundation, not a playable multiplayer release.
