# World-state protocol foundation

The new protocol starts with explicit little-endian serialization rather than sending C++ structs or framebuffer pixels. Version 2 defines a full `WorldSnapshot` packet with a server tick, scene revision, UTF-8 Activity class/preset/module and Scene module/preset identity, and a list of objects. Each object record carries a stable server-assigned network ID, class/module/preset names, transform and velocity, health, team, and flags. Version 2 is intentionally incompatible with the experimental version 1 wire format so a client cannot misread a snapshot that lacks the content identity required to load modded Activities and Scenes.

The 16-byte packet header contains the `CCR1` magic, protocol version, message type, reserved byte, sequence number, and payload length. The decoder rejects unknown versions and message types, truncated or oversized packets, invalid UTF-8, non-finite numeric values, duplicate/zero object IDs, invalid team IDs/object categories, and object/string counts beyond fixed bounds. It does not rely on compiler struct packing or endianness.

`-debug-run` performs an in-process round-trip check with a Cyrillic preset name and verifies that truncated packets, unsupported versions, and duplicate network IDs are rejected. The codec is transport-independent so it can be carried over the repository's RakNet dependency.

`WorldStateSnapshotBuilder` captures top-level actors, items, and particles from `MovableMan`. It assigns monotonically increasing server network IDs and tracks them against host-local runtime UIDs for each live object's lifetime; stale mappings are removed after the object disappears. It increments the scene revision when Activity or Scene identity changes, including class and module, and marks actor/item/particle categories in object flags. At the end of its automated gameplay smoke run, debug mode broadcasts this snapshot through a local RakNet server to four clients. Each client decodes it and checks Activity/Scene identity, tick, object count, and the first object preset; the run also repeats capture to verify IDs and revision remain stable. The same debug run applies a snapshot twice through `WorldStateClientReplica`, applies an empty snapshot to remove client-created replicas, then restores the world to check creation, removal, and idempotent updates. Packet size and pass/fail go to `ScreenShots/DebugRuns/DebugRun.log`. Attached equipment and actor inventories, terrain state/deltas, and object creation/deletion history are not captured by the snapshot. Network IDs are local to a host session and restart when that session is recreated.

`WorldStateTransport` is the RakNet adapter for connected peers. Its typed `SendSnapshot` and `BroadcastSnapshot` methods encode snapshots before reliable ordered delivery. `WorldStateClientSession` handles connection events, validates snapshots, rejects stale sequences, and retains the latest decoded state. `WorldStateClientReplica` runs on the simulation thread, associates network IDs with local objects, updates transforms/velocity/rotation/health/team, clones new objects from the same local `.rte` preset, and removes client-owned clones when they disappear from a later full snapshot. Existing locally owned objects are not destroyed on server absence because Activities may retain direct brain/actor pointers. Client-owned replicas still run local gameplay updates between received snapshots. The debug run verifies idempotent updates and removal/restoration of cloned replicas. With `-world-state-server`, an in-process host session polls joins/leaves and broadcasts current snapshots at 20 Hz from the simulation loop when at least one client is connected. It skips object-list capture and packet encoding while empty. The debug run verifies that idle behavior, connects four client sessions to this actual host, confirms all receive a snapshot, disconnects them, and verifies the host stays alive. It separately exercises raw transport and malformed protocol packets. Protocol version 2 builds and passes the host/client smoke on Windows x64 and Ubuntu 24.04 x86_64; the Linux offscreen run loaded modules in 8.22 s and completed in 12.04 s. Debug runs skip audio initialization to avoid a native FMOD worker-thread shutdown crash reproduced on Linux; normal game launches keep their existing audio behavior.

The legacy framebuffer `NetworkServer` and `NetworkClient` sources remain excluded from both build systems and implement a different remote-frame protocol. An experimental host can be started with `Cortex Command.debug.minimal.exe -world-state-server 8000 -world-state-bind 0.0.0.0 -world-state-players 8`. It starts the built-in Tutorial Activity, listens on the chosen IPv4 address/port, accepts up to 64 RakNet peers, broadcasts snapshots at 20 Hz while simulation updates, and writes connection/status messages to `WorldStateServer.log`. The port is optional (default `8000`); bind address and player limit default to `0.0.0.0` and `8`.

A graphical client can now connect with `Cortex Command.debug.minimal.exe -world-state-client 192.0.2.10 8000`. On startup it waits up to 15 seconds for a valid snapshot, resolves the Activity and Scene using the server-provided `.rte` module names, starts that local content, and applies subsequent snapshots. Connection identity and periodic application counts are written to `WorldStateClient.log`. This path has been exercised as two independent Windows processes against a local host; the client applied over 100 snapshots for `GATutorial/Tutorial Mission` and `Missions.rte/Tutorial Bunker`. Closing the game stops its network session.

This is still an early authoritative-state prototype, not full gameplay networking. The client keeps its local simulation active between snapshots; attached items/inventories, complete Lua/Activity state, terrain changes, object-specific state (for example weapon ammunition), networked player input, reconnect/session negotiation, and deterministic interpolation are not replicated. Some remote objects may not have a compatible local preset and are skipped with diagnostics. The host still initializes SDL and rendering; non-snapshot client packets are rejected. A GPU-free dedicated-server executable remains unimplemented.
